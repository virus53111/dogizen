# MURDILIMAX: ShopClass classifieds portal (staging deployment)

The owner requested to replace **murdilimax.com** with an actual classifieds / real-estate listing portal, removing previous game and recovery sites from the *public domain*. This uses **the official ShopClass 7.0.16 PHP/MySQL engine**, not a static marketplace mockup or new custom app.

## Safe rollout

1. A restorable archive of the previous site and all old project files is preserved in GitHub branch `archive/murdilimax-before-classifieds-20261108` at commit `964d6115de539ca33c9307bc81be98bcf65cd6b4`.
2. Production configuration in `render.yaml` declares a separate private MariaDB server with persistent storage and a separate ShopClass web server with durable photo/theme uploads. Secrets are generated by Render; admin e-mail is entered during approval and never committed.
3. `compose.test.yaml` is a disposable, local-only CI stack. It launches the *real* official ShopClass image, provisions a database and checks a live homepage and administrator login.
4. **Do not replace DNS or GitHub Pages until ShopClass production service is deployed, installed, admin login secured, email configured, backups prepared and a test ad with photos survives a restart**.
5. Add `murdilimax.com` and (optionally) `www.murdilimax.com` as custom domains in Render. Set `WEB_PATH=https://murdilimax.com/`. Update the domain's DNS in its registrar as instructed by Render and verify HTTPS.
6. Only then retire the old public GitHub Pages site and its /guide/ and /recovery/ paths. Keep the archive branch for rollback; deletion of unrelated repositories is deliberately out of scope.

## What ShopClass supports

- Classifieds / property / vehicles / jobs categories
- User accounts and ad management
- Photographs and location filters
- Search, listing detail pages, moderation and abuse reports
- Administrator dashboard at `/oc-admin/`
- Optional promoted/paid listings; **leave payments disabled until separately configured and tested**

## Hosting and prerequisites

**Not compatible with GitHub Pages**: it requires PHP 8+, a durable MySQL/MariaDB database and storage for uploaded photos. The Render Blueprint currently requests **two paid Starter-class services and two persistent 5 GB disks**. It is a *proposal*, not approved or deployed automatically. Render prices and availability must be reviewed before approval.

The account's currently connected Render environment does not provide a ready managed MySQL instance for this site. Do not expose MariaDB publicly. The database in this template is a private service accessible only through Render private networking.

The ShopClass image is pinned to `ghcr.io/mindstellar/shopclass:7.0.16` and MariaDB to `mariadb:11.4`. Official docs: https://mindstellar.com/docs/deploy/docker/ .

**Deployment requirements not yet supplied**: production administrator contact e-mail, paid hosting authorization, and DNS access to the domain registrar. Neither secrets nor payment details should be posted in GitHub or this repository.

Before public launch: configure CAPTCHA and anti-spam, SMTP transactional e-mail, privacy policy and terms, categories and country/city data, persistent backup automation, and an abuse-reporting process.

## Backups

MariaDB data persists in a dedicated mounted disk; this is not a backup on its own. Configure daily logical database dumps and replicate both those dumps and `/application/oc-content` uploads to independent object storage. Verify a restore before accepting real-user listings. Do not replace the old deployment or delete its data prematurely.

## Testing without paid hosting

GitHub Actions `Validate ShopClass deployment` runs the real PHP+MariaDB stack on a short-lived Ubuntu test runner. If the test fails, the Docker image, proxy config or bootstrap may need adjustment. A green CI run does **not** substitute for production DNS, e-mail or backups.
