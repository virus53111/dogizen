# Murdilimax Local Profile API v2 — developer beta

**Не является облачным API Dolphin Anty.** Это локальный интерфейс управления собственными профилями на одном компьютере. Он не экспортирует cookies, токены, пароли, историю или данные сайтов и не даёт доступа к платежам. Вызывается только на `127.0.0.1:18765` с секретным ключом из системного хранилища.

## Запуск из программы Windows v0.7

Откройте Murdilimax Browser → «О программе» → **«▶ Локальный API»**. При первом запуске ключ создаётся в системном хранилище и отображается один раз. Сохраните его в менеджере секретов. «■ Остановить API» закрывает порт. «↻ Новый ключ API» отключает текущий сервер и делает старый ключ недействительным. Закрытие программы также останавливает сервер. Ничего не включается автоматически.

Другой способ для разработчиков (из папки исходников):

```powershell
python browser/app.py --api-rotate-token
python browser/app.py --api-server
```

Установленная EXE-сборка Windows работает с теми же параметрами, но окно программы собрано без консоли. Для обычной работы удобнее пользоваться кнопками.

## HTTP API

Все запросы используют заголовок `Authorization: Bearer <64 hex символа>`. JSON запросы требуют `Content-Type: application/json` и тело не более 4096 байт. Нет CORS, заголовок Origin запрещён, Host проверяется. Данные пользователя остаются на компьютере.

| Метод | Маршрут | Что делает |
|---|---|---|
| GET | `/v1/health` | Состояние, `api_version: 2` |
| GET | `/v1/profiles` | Список профилей, ID, имя, группа, теги и состояние |
| GET | `/v1/profiles/<id>` | Один профиль, без URL и секретов |
| GET | `/v1/proxies` | Только ID и имена прокси, **без** адресов/логинов/паролей |
| POST | `/v1/profiles/quick` | Создать 1–10 пустых профилей; JSON `{"count":1,"name_prefix":"New"}` |
| POST | `/v1/profiles/<id>/duplicate` | Копировать только метаданные, **не** cookies или сессии |
| PATCH | `/v1/profiles/<id>` | Изменить остановленный профиль: `name`, `group`, `tags`, `url`, `startup_urls`, `proxy_id` |
| POST | `/v1/profiles/<id>/start` | Запрос запуска профиля |
| POST | `/v1/profiles/<id>/stop` | Запрос остановки профиля |

Любая новая операция создания профиля проверяет **реальную серверную лицензию**, если она выходит за бесплатные 3 профиля. Клиент не принимает лимит из HTTP-запроса. Дочерний процесс проверяет лицензию при запуске повторно. При сетевой недоступности платные операции запрещены; существующие бесплатные профили доступны без оплаты.

Изменять fingerprint, читать пароли прокси, экспортировать cookies или удалять профили через API нельзя. Это отдельная необходимая проверка безопасности, а не ошибка интерфейса.

## Пример PowerShell

```powershell
$token = Read-Host 'Введите ключ API'
$headers = @{ Authorization = "Bearer $token" }
Invoke-RestMethod -Uri 'http://127.0.0.1:18765/v1/profiles' -Headers $headers
Invoke-RestMethod -Method Post -Uri 'http://127.0.0.1:18765/v1/profiles/quick' -Headers $headers -ContentType 'application/json' -Body '{"count":1,"name_prefix":"QA"}'
Remove-Variable token, headers
```

**Не вставляйте токен в скриншоты, браузерные адреса, GitHub Issues, команды из истории shell или публичные проекты.** В версиях 0.6 и ранее API имеет только список/запуск/остановку, без этих новых операций.

## Критерии публикации

- [ ] Полный `unittest discover -s browser` на Windows, Linux, macOS, включая HTTP 401/403/409 и запрет URI со встроенными паролями
- [ ] Настоящий Camoufox запускается и сохраняет данные при перезапуске; лицензия не обходится через новый API
- [ ] PyInstaller Windows EXE, реальная установка Setup.exe и самопроверка установленного приложения
- [ ] На физическом Windows 10 и Windows 11 пользователь включает API кнопкой, копирует ключ и получает список; закрытие окна освобождает порт
- [ ] Проверка дизайна, сайта и Stripe LIVE в режиме только чтения после публикации

Пока невыполненные пункты не подтверждены, продукт остаётся бетой; сложные функции облачной синхронизации и командной работы пока отсутствуют.
